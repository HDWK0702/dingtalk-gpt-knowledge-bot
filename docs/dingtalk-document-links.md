# 知识回答附钉盘文档链接

在对应知识笔记开头配置 `dingtalk_document_url`，检索命中后，程序在参考资料下显示“查看钉盘文档”。不需要修改卡片模板，也不需要下载 Excel。

## 配置示例

以下仅为格式示例，URL 不代表真实文件，使用时替换为从钉盘复制的完整 HTTPS 分享链接。

```markdown
---
title: 报销申请表填写说明
status: active
department: 财务
dingtalk_document_url: https://alidocs.dingtalk.com/i/nodes/REPLACE_WITH_REAL_SHARE_LINK
---

## 报销申请表

办理报销时，填写钉盘中的报销申请表，并按照表内要求准备附件。
```

`department` 按资料实际权限填写，不要直接照抄“财务”。其他已有状态、排除等字段保持不变。

回答会包含正文与参考资料，例如《报销申请表填写说明》下方的“查看钉盘文档”可点击打开对应文件。

## 段落与文档怎样对应

这是笔记级字段，该笔记切分出的所有片段都继承同一链接。如果只有某一段需要链接，或不同段落对应不同文档，请将相关段落整理为独立小笔记，再分别填写链接。不要把只适用于一小节的文件链接配置到整本大手册上。

正文仍需写清“什么时候查看这个文件”和用途，供检索匹配。只保存 URL、没有主题说明，不能保证正确命中。链接附在已选中的参考资料下，不自动定位到生成答案中的某一句；来源数量沿用现有上限。不完整答案的相关资料摘要也附上该入口。

## 生效与验证

1. 本地代码上线后，更新对应知识笔记。
2. 当前生产使用 PostgreSQL 向量索引，修改笔记后需要按现有流程更新索引；只保存 Markdown 不会自动改动现有索引。
3. 提问与笔记主题相关的问题，检查参考资料出现链接；问无关问题，检查未误附链接。
4. 用实际员工身份点击，检查电脑/手机跳转及文件访问权限。

程序只使用检索结果元数据中的链接生成入口，忽略空值、非 HTTPS、带登录凭据或格式异常的 URL。格式检查不验证链接是否有效、过期或有权访问。程序不请求钉盘、不更改文件权限，现有知识检索过滤保持不变。

卡片显示 Markdown 链接；卡片失败后的文本回退保留地址，具体点击表现需客户端实测。普通聊天模式不检索知识库，也不会自动附加该入口。

本次仅完成本地功能，尚未部署、重建生产索引或绑定真实分享链接，未验证钉钉客户端跳转。
