# 企业知识库问答机器人

一个面向企业内部资料的 RAG 问答项目：员工在钉钉提问，系统先按业务域和权限检索已发布资料，再由大语言模型生成带来源的回答。

## 项目亮点

- 钉钉 Stream 机器人：员工在熟悉的聊天入口提问。
- Markdown/Obsidian 知识源：支持章节化文档、版本和生效状态。
- 业务域隔离：产品资料与新人培训资料不会默认串库。
- Embedding + pgvector 兼容设计：按语义检索相关内容。
- 保守回答：找不到足够依据时拒答，不让模型凭空补充。
- 上下文记忆：分析新问题是否承接上一轮，再决定是否带入上下文。
- 失败切换、去重、日志和分阶段耗时记录：便于稳定性和性能排查。
- Docker 化运行：可从本地迁移到 ECS、RDS、Redis 和 OSS。

## 架构

```text
钉钉 Stream
    ↓
FastAPI / Python 服务
    ↓
问题分析、业务域过滤、权限过滤
    ↓
Embedding → 向量检索 →（可选重排序）
    ↓
大语言模型生成答案和来源
    ↓
钉钉回复 + 问答/性能日志
```

## 如何查看效果

### 方式一：打开交互式演示

直接打开 [`demo/index.html`](../demo/index.html)，或将仓库发布到 GitHub Pages。页面内置虚构资料和三组演示问题，适合让招聘方先体验整体交互。页面明确标注为 Demo，不会伪装成真实模型调用。

### 方式二：看演示资料

`demo/knowledge/` 是专门为公开展示准备的虚构资料，不含企业内部文件。可用它展示三类场景：

1. 产品资料问题：返回产品说明和来源。
2. 新人培训问题：只命中培训资料，不引用产品资料。
3. 无依据问题：明确拒答并建议联系管理员。

### 方式三：本地运行

1. 复制 `.env.example` 为 `.env`，填入你自己的钉钉、模型和 Embedding 配置。
2. 将 `OBSIDIAN_VAULT_PATH` 指向演示知识库或你自己的知识库。
3. 先运行 `run_chunk_preview.bat` 检查切分结果，再运行 `重建索引.bat` 建立向量索引。
4. 运行 `启动钉钉机器人.bat`，在测试群中提问。

公开仓库不要放真实 `.env`、真实 Obsidian 文件、问答日志、性能日志或 `rag_index.json`。

### 发布成公开网址

仓库内已附带 GitHub Pages 配置：`.github/workflows/deploy-demo.yml`。
把项目推送到 GitHub 的 `main` 分支后，在仓库的 **Settings → Pages** 中将
发布来源设为 **GitHub Actions**。之后每次更新 `demo/`，GitHub 会自动发布，网址通常是：

`https://你的用户名.github.io/仓库名/`

作品集页面只展示 `demo/` 下的虚构资料和静态交互，不会调用你的模型 API，
因此招聘方无需账号或密钥即可体验。真实钉钉机器人继续在你的本地或内网运行。

## 建议录制的 60 秒演示

1. 在钉钉输入“第三类医疗器械办理需要哪些材料”，展示系统命中培训资料并给出来源。
2. 追问“那办理周期呢”，展示上下文承接。
3. 输入一个资料中没有的问题，展示保守拒答。
4. 打开脱敏后的性能日志，展示检索和模型阶段耗时。

截图或视频中请遮挡员工姓名、手机号、群名称、内部文件名、API 地址和任何密钥。

## 生产化方向

当前仓库适合展示和小规模试运行。正式部署时，把本地文件和 JSON 索引替换为 OSS、RDS PostgreSQL + pgvector，并将 Redis、日志、监控和密钥管理接入云服务。
